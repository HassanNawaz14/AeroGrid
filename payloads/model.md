## WP-07 physical data model reconciliation (2026-11-13)

The conceptual description above includes **3D cells and altitude bands**, while the deployed `project_dw.dim_spatial_grid` table has only `grid_cell_id`, `site_key`, `lat_bin`, and `lon_bin`. Actual WP-07 bins are site-specific **0.01-degree 2D WGS84 cells** created only from real accepted observations. `fact_airspace_occupancy` grain is `(time_key, grid_key, algorithm_version)`; it is **not** a distinct altitude-band occupancy snapshot. On the persisted data snapshot, `dim_spatial_grid` contains 3,658 real cells plus one `-1` unknown row, and occupancy holds 1,754 `wp07-v1` rows.

`fact_close_encounter` and `fact_restriction_activation` tables now exist, but each has **zero** real rows. The deployed close-encounter algorithm requires exact timestamps; diagnostic near-time queries were never promoted to the algorithm. No matching historical FAA restriction snapshots are available for the January 2022 Tartan data. Treat the conceptual 3D fields as *planned design*, not stored columns. Correcting the physical model to 3D requires an explicit schema/grain decision and migrations; do not silently relabel existing 2D facts.
