# AeroGrid Phase 2 Data Dictionary

## Status

This is the column-level logical dictionary for the Phase 2 model. It is synchronized
with [`../Phase2/docs/04_data_model.md`](../Phase2/docs/04_data_model.md) and
[`diagrams/aerogrid_schema.dbml`](diagrams/aerogrid_schema.dbml). `WP-04` staging DDL
and loaders and `WP-05` dimensions DDL/seeds are `DONE` and applied on Neon with
reader `SELECT` grants in place. `WP-06` core movement facts DDL/loaders (`fact_vehicle_tracking`
and `fact_flight_journey`) are implemented on the `WP-06` branch pending Member C's
real `dim_vehicle` completion (`03_seed_real.sql`) and CI acceptance verification.
Derived-fact DDL remains authorized only inside `WP-07`.

Physical DDL may use equivalent PostgreSQL types, but names, grains, keys, and
meanings must match this dictionary.

## Conventions

| Topic | Rule |
|---|---|
| Schema | `project_staging`, `project_dw`, `project_reporting` |
| Time | `TIMESTAMPTZ`, stored in UTC |
| Surrogate keys | `BIGINT GENERATED BY DEFAULT AS IDENTITY` |
| Unknown member | `-1` in every dimension |
| Natural keys | Unique constraints; source-scoped where needed |
| Altitude | MSL and AGL stored separately with a source/datum label |
| Distance | Nautical miles |
| Speed | Knots |
| Coordinates | WGS84 decimal degrees |
| Provenance | Every fact has a source or algorithm lineage and `etl_run_id` |
| Nulls | Unknown optional measures are `NULL`, not zero |
| SCD | Type 1 for Phase 2 |

## Dimension tables

### `project_dw.dim_time`

Grain: one UTC hour.

| Column | Logical type | Key | Null | Description |
|---|---|---|---|---|
| `time_key` | BIGINT identity | PK | no | Surrogate key |
| `hour_ts` | TIMESTAMPTZ | unique | no | Start of the UTC hour |
| `date_utc` | DATE | | no | Calendar date in UTC |
| `hour_utc` | SMALLINT | | no | Hour 0-23 UTC |

Unknown member: `-1`, `hour_ts = 1900-01-01 00:00:00+00`.

### `project_dw.dim_site`

Grain: one monitored site or analytical region.

| Column | Logical type | Key | Null | Description |
|---|---|---|---|---|
| `site_key` | BIGINT identity | PK | no | Surrogate key |
| `site_code` | TEXT | unique | no | `KBTP`, `KAGC`, `NIGHTJAR_PA`, `DJI_CO` |
| `site_name` | TEXT | | yes | Human-readable site name |

Unknown member: `-1`, `site_code = 'UNKNOWN'`.

### `project_dw.dim_vehicle`

Grain: one real vehicle identity within a source system.

| Column | Logical type | Key | Null | Description |
|---|---|---|---|---|
| `vehicle_key` | BIGINT identity | PK | no | Surrogate key |
| `source_system` | TEXT | unique pair | no | Source that establishes the vehicle |
| `source_entity_id` | TEXT | unique pair | no | Source-scoped vehicle identity |
| `vehicle_type` | TEXT | | yes | Vehicle category |
| `first_seen_ts` | TIMESTAMPTZ | | yes | First real observation |
| `last_seen_ts` | TIMESTAMPTZ | | yes | Last real observation |

Unique: `(source_system, source_entity_id)`.

Unknown member: `-1`, `source_system = 'UNKNOWN'`, `source_entity_id = 'UNKNOWN'`.

Do not merge identities from different sources without a recorded decision.

## Unknown-member policy

- Every dimension has a `-1` row.
- Required unresolved keys reject the fact row.
- Optional unresolved keys use `-1` and increment a DQ counter.
- `-1` is not a business value and must be excluded from business averages.
- Reports must show the count of unknown-member facts.

## Provenance policy

Every fact row must trace to:

```text
fact row
  -> source_system + source_record_id or algorithm input IDs
  -> source_manifest (URL, license, SHA-256, fetched_at)
  -> raw object key
  -> staging accepted row
```

Derived facts also record `algorithm_version` and the ETL run.
