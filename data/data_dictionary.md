# AeroGrid Phase 2 Data Dictionary

## Status

This is the column-level logical dictionary for the Phase 2 model. It is synchronized
with [`../Phase2/docs/04_data_model.md`](../Phase2/docs/04_data_model.md) and
[`diagrams/aerogrid_schema.dbml`](diagrams/aerogrid_schema.dbml). No tables exist yet;
physical DDL is authorized only inside the owning work package (`WP-04` staging, `WP-05`
dimensions, `WP-06`/`WP-07` facts).

Physical DDL may use equivalent PostgreSQL types, but names, grains, keys, and
meanings must match this dictionary.

## Conventions

| Topic | Rule |
|---|---|
| Schema | `project_staging`, `project_dw`, `project_reporting` |
| Time | `TIMESTAMPTZ`, stored in UTC |
| Surrogate keys | `BIGINT GENERATED BY DEFAULT AS IDENTITY` |
| Unknown member | `-1` in every dimension |
| Natural keys | Unique constraints; source-scoped where needed |
| Altitude | MSL and AGL stored separately with a source/datum label |
| Distance | Nautical miles |
| Speed | Knots |
| Coordinates | WGS84 decimal degrees |
| Provenance | Every fact has a source or algorithm lineage and `etl_run_id` |
| Nulls | Unknown optional measures are `NULL`, not zero |
| SCD | Type 1 for Phase 2 |

## Relationship summary

|---|---|---|
| `fact_vehicle_tracking` | time, site, vehicle, grid | weather (`-1`) |
| `fact_flight_journey` | vehicle, site, start time, end time | origin/destination grid |
| `fact_close_encounter` | start time, site, grid, two vehicles | weather (`-1`) |
| `fact_restriction_activation` | time, site, zone | none |
| `fact_airspace_occupancy` | time, site, grid | none |

## Unknown-member policy

- Every dimension has a `-1` row.
- Required unresolved keys reject the fact row.
- Optional unresolved keys use `-1` and increment a DQ counter.
- `-1` is not a business value and must be excluded from business averages.
- Reports must show the count of unknown-member facts.

## Provenance policy

Every fact row must trace to:

```text
fact row
  -> source_system + source_record_id or algorithm input IDs
  -> source_manifest (URL, license, SHA-256, fetched_at)
  -> raw object key
  -> staging accepted row
```

Derived facts also record `algorithm_version` and the ETL run.
