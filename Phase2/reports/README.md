## Evidence rules

- Counts and DQ results must come from real `project_dw` and `project_staging` rows.
- Show latest ETL audit run separately from ETL run-level input/accepted/rejected/duplicate reconciliation; do not add separate table totals and call them a source batch.
- Preserve source URLs, license, attribution, full SHA-256 and raw-object provenance.
- Display warnings as warnings, with observed values and readable interpretations.
- Disclose that weather observations and FAA snapshots have limited or absent source coverage, and that inferred airborne status is not the original observed ground state.
- Never fabricate encounters, restrictions, warehouse facts, or DQ passes.
- Keep secrets, raw payloads, `.env` files and database URLs out of the PDFs and Git history.

## Reproducing after an approved code change

1. Push the source change to a feature branch and run the full tests.
2. Dispatch `WP-09 Generate evidence-backed PDF reports` using **that branch**, so the workflow checks out the modified generator.
3. Download the `aerogrid-wp09-pdf-reports` artifact from the successful run.
4. Extract both PDFs into this directory, open them, and check the counts and limitations against Neon.
5. Commit PDFs to the same review branch and merge through a pull request.

**Note:** ReportLab test fixtures may generate fake values in temporary test folders for layout/unit testing. These are never publishable warehouse evidence or final reports.
